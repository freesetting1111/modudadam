# 모두다담 제품·기술 기준서

## 1. 제품 정의

모두다담은 일상에서 반복해서 기록하고 탐색하는 주제를 한곳에 모은 모바일 우선 생활 플랫폼이다. 비회원도 모든 공개 콘텐츠를 읽고 검색할 수 있다. 글 작성·수정·삭제, 댓글, 반응, 저장, 개인 기록처럼 DB 상태를 변경하는 작업은 일반 계정 또는 카카오·네이버 로그인 후에만 가능하다.

핵심 가치는 탐색, 축적, 재방문이다. 사용자는 로그인 전에 유용한 정보를 발견하고, 로그인 후 자신의 생활 기록과 관심 콘텐츠를 쌓으며, 기록 변화·교류·추천 때문에 다시 방문한다.

## 4. 인증

- 도메인 없이도 개발 가능한 아이디·비밀번호 기반 일반 회원가입/로그인을 제공한다.
- 일반 회원은 아이디, 비밀번호, 이름, 휴대폰 번호, 이메일을 필수로 받으며 게시판에는 아이디를 표시한다.
- 회원가입은 아이디 중복 확인을 완료한 경우에만 진행한다.
- 아이디는 영문·숫자·밑줄 4~12자리, 비밀번호는 공백 없이 영문·숫자를 포함한 8~20자리로 제한한다.
- 이름은 공백 없이 한글·영문 2~30자리, 휴대폰은 국내 이동통신 번호 형식, 이메일은 ASCII 이메일 형식만 허용한다.
- 비밀번호는 scrypt와 사용자별 무작위 salt로 해시하며 평문을 저장하지 않는다.
- 동일 계정의 로그인 실패가 5회 누적되면 10분 동안 잠근다.
- 아이디 찾기는 이름과 이메일 확인 후 이메일 인증을 완료해야 마스킹된 아이디를 표시한다.
- 비밀번호 찾기는 아이디와 이메일 확인 후 이메일 인증을 완료해야 새 비밀번호를 설정할 수 있다.
- 이메일 인증번호는 영문 대문자·소문자·숫자·특수문자를 모두 포함한 8자리이며 해시로 저장하고 5분 만료, 5회 시도 제한을 적용한다.
- 카카오·네이버 OAuth 2.0 Authorization Code를 사용한다.
- state nonce를 HttpOnly 쿠키와 대조해 CSRF를 방지한다.
- 공급자 사용자는 `(provider, provider_user_id)`로 식별한다.
- 로그인 시 무작위 세션 토큰을 발급하고 DB에는 SHA-256 해시만 저장한다.
- 세션 쿠키는 HttpOnly, SameSite=Lax, 14일 만료를 기본으로 한다.
- 공개 조회에는 세션이 필요 없다.
- OAuth 비밀키와 공급자 access token은 브라우저에 노출하지 않는다.

## 5. 데이터 모델

- `users`, `user_local_accounts`, `user_oauth_accounts`, `user_sessions`: 회원·일반 계정·소셜 계정·세션
- `categories`: 12개 대분류와 노출 순서
- `boards`: 카테고리별 게시판의 이름·읽기·쓰기 권한 설정
- `posts`: 카테고리 공통 콘텐츠. 확장 속성은 `attributes jsonb`
- `comments`, `post_reactions`, `post_bookmarks`: 커뮤니티 상호작용
- `tags`, `post_tags`: 검색·분류
- `user_records`: 반려동물·식단·운동·차량 등 개인 기록 공통 저장소
- `access_logs`: 페이지뷰·클릭·유입·기기·경로 원천 이벤트
- `user_attributions`: 익명/회원의 최초·최근 유입 요약

초기부터 카테고리별 테이블 12개를 만들지 않는다. 공통 게시물/기록 + JSONB로 사용성을 검증하고, 무결성과 쿼리 요구가 커지는 영역만 전용 테이블로 승격한다.

## 6. 분석 원칙

`gongbu-eong`과 같은 방향으로 로그인 전 유입부터 보존한다.

- 최초 접근 시 `anonymous_id`를 생성해 localStorage에 저장한다.
- page path, query, title, referrer, landing URL, UTM 5종, gclid/fbclid, user agent, locale, timezone, viewport, device type을 수집한다.
- 로그인 전후 이벤트는 `anonymous_id`와 `user_id`로 연결 가능하게 저장한다.
- IP는 원문 대신 서버 비밀값을 섞은 해시만 보관하는 것을 운영 원칙으로 한다.
- 민감한 입력값, OAuth token, 게시글 본문은 이벤트 속성에 넣지 않는다.
- 운영 대시보드는 추후 일/주 집계 테이블을 별도로 사용한다.

## 7. UI 원칙

- 모바일 웹이 기본이며 앱 설치를 전제로 하지 않는다.
- 콘텐츠 셸은 최대 `600px`; 넓은 화면에서는 중앙 정렬한다.
- 360px부터 유동적으로 동작하고 주요 터치 영역은 최소 44px이다.
- 다나와 모바일처럼 검색, 카테고리 그리드, 추천 콘텐츠, 고정 하단 탐색을 우선한다.
- 공개 콘텐츠를 먼저 보여주고 쓰기 동작에서 로그인으로 연결한다.
- 첨부된 다람쥐를 공식 캐릭터와 파비콘으로 사용한다.

## 8. 초기 API

- `GET /api/health`: 서버·DB 상태
- `GET /api/categories`: 공개 카테고리
- `GET /api/posts`, `GET /api/posts/:id`: 공개 글 조회
- `POST /api/posts`: 로그인 사용자 글 작성
- `PATCH/DELETE /api/posts/:id`: 작성자 수정·소프트 삭제
- `POST /api/access-logs`: 익명 포함 접근 이벤트
- `GET /api/auth/oauth/{provider}/start|callback`: OAuth
- `POST /api/auth/register`, `POST /api/auth/login`: 일반 회원가입·로그인
- `GET /api/auth/check-login-id`: 회원가입 아이디 중복 확인
- `POST /api/auth/recovery/find-id/request|confirm`: 이메일 인증 기반 아이디 찾기
- `POST /api/auth/recovery/password/request|confirm`: 이메일 인증 기반 비밀번호 재설정
- `GET /api/auth/me`, `POST /api/auth/logout`: 세션
- `GET/POST /api/posts/:id/comments`: 공개 댓글 조회·회원 댓글 작성

## 9. 구현 단계

1. 기반: 초기 SQL, DB 연결, OAuth, 세션, 공개 카테고리/글, 접근 로그
2. 커뮤니티: 댓글, 반응, 북마크, 신고, 검색
3. 기록: 카테고리별 기록 UX와 필요한 전용 테이블
4. 운영: 관리자, 집계 분석, 광고·제휴 슬롯, 알림
5. 확장: 추천, 구독, 유료 보관·분석

현재 구현 범위는 일반·소셜 인증과 12개 카테고리 게시판의 목록, 상세, 글쓰기, 댓글까지다.
